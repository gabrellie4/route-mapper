# Route Mapper

A local tool for laying out parking occupancy count routes and generating inventory
IDs, distances and walk-time estimates before field work. Built for Oakland parking
surveys (Fruitvale, Grand Lake, Jack London study areas).

## Running it

`python3 route_mapper.py` uses the standard library only (no pip, no virtualenv). It
starts a server on 127.0.0.1:8765 and opens a browser.

- `ROUTE_MAPPER_PORT` overrides the port. `main()` exits if the port is busy.
- `ROUTE_MAPPER_DIR` overrides the save directory. The default is `route_projects/`
  next to the script, not the launch directory. It is gitignored because it holds
  survey data, not source.
- `serve(port, open_browser)` starts the server without blocking, for Jupyter/Colab,
  and moves to the next free port if one is busy. `stop()` shuts it down.

There is no test suite. To check the engine, load the module and call `compute()` on
a `new_project()` with a few `new_segment()`s. When you run it from a script, use
`serve(..., open_browser=False)`, because `main()` always opens a browser.

## The design rule

Python owns the model. The browser posts geometry and renders what comes back. It
never calculates an ID, a distance or a duration.

The browser decides only where a lot's line is pinned (and Reverse direction).
Python turns that into the order.

### Parking lots

A lot is drawn as a polygon and tied to the route by a line. It stores
`anchor_leg` (the uid of a non-lot leg) and `anchor` ([lat, lng] on that leg).
`_walk_order()` in `compute()` counts the lot just before that leg if the anchor
falls on the leg's first half, and just after it if the second half. Lots on one leg
go in anchor order. `compute()` returns segments in this walking order, so the list
and the next save follow it. It also sets the derived `anchor_at` (the anchor
projected onto the leg) for drawing.

In the UI:

- `finishLot` ties a new lot to the nearest point on the route (`attachLot` /
  `nearestOnRoute`). `drawLotLine` draws the line and a draggable pin only for the
  selected lot.
- `push()` calls `reattachLots()`, so a lot whose leg was deleted or merged is re-tied
  to the nearest remaining leg.
- ↑/↓ on a tied lot move its anchor to the start of the previous leg or the end of the
  next one. ↑/↓ on a leg step past tied lots, which ride with their leg.
- An untied lot (no `anchor_leg`, or a leg that no longer exists) keeps its list
  position.

The line marks order only. It adds no distance.

History: v1 guessed a lot's position from its shape (`lotInsertIndex` / `attachLot`)
and often guessed wrong. v2 (Nov 2026) turned a routed leg into the lot, but the route
then had to walk into and out of the polygon, which looked wrong, so the user asked
for this design. Don't bring back either of the earlier ones.

## Architecture

`compute(project)` is the single source of truth and is pure. It deep-copies the
project with a JSON round-trip, runs `migrate()`, fills in every derived field, and
returns a new project. The UI calls it on every edit, through `POST /api/state`.
Every export except the JSON project file calls it first. The JSON export is the raw
project, on purpose.

The data model is plain dicts and is JSON-serialisable:

- **project**: `name`, `settings`, `center`, `zoom`, `basemap` (set but unused by the UI),
  `routes[]`. New projects open on all of Oakland (`OAKLAND_CENTER`, `OAKLAND_ZOOM`).
- **route**: `uid`, `name`, `prefix` (the zone number), `color`, `start`, `end`,
  `visible`, `segments[]`
- **segment**: `uid`, `kind`, `pts[]`, `spaces`, `manual_id`, `flagged`, `note`,
  `street`, plus the optional flags `is_route_start` / `is_route_end`. Lots may also
  have `anchor_leg` / `anchor` (see Parking lots above) and `minutes_manual` (minutes
  a planner typed, replacing the suggested lot time). There is also `label_pos`,
  which `compute()` still reads but nothing sets any more.
- **settings**: `minutes_per_block`, `spaces_per_block`, `ft_per_space`,
  `lot_sqft_per_space`, `walk_speed_ft_per_min`, `skip_multiples_of_ten`.
  `clean_settings()` fills missing keys from `DEFAULT_SETTINGS` and replaces null or
  non-numeric values (an emptied box in the UI) with the default, so old projects and
  half-typed settings both compute.

`kind` is one of:

- `count`: a counted block face. It gets an ID.
- `walk`: a connector leg. It renders dashed and never gets an ID.
- `lot`: a parking lot polygon (`pts` is the ring). It gets an ID in route order.

Old projects kept lots in a top-level `lots` list. `migrate()` folds them into the
segment list. Lots saved before lot lines existed are untied and keep their list
position until someone uses **Attach to the route**.

**Derived fields must not be saved.** The UI's `strip()` (about line 2154) deletes them
before posting back. If you add a derived field to `compute()`, add it to `strip()` too.
The newest ones are `spaces_est` and `minutes_suggested`.

## `IdSequence`: be careful here

IDs are never stored. They're derived from route order on every compute, so inserting
a block renumbers everything after it. The format is `<prefix>.<n>`, and it skips every
multiple of ten: `2.1`…`2.9`, then `2.11`, with no `2.10` or `2.20`. The source data
does this on purpose in all four zones, and Survey123 compatibility depends on it.
`skip_multiples_of_ten` in settings turns it off. (The README says this was checked
against the real Fruitvale zone 2 and Grand Lake zone 1 ID sets. No such data or test
exists in this repo.)

Invariants in `compute()`:

- The start marker takes the first slot, so block faces normally begin at `.2`. This
  stops two `2.1`s from appearing.
- A count or lot segment flagged `is_route_start` / `is_route_end` stands in for that
  endpoint. It keeps its own ID, no extra number is spent, and the shared ID is not
  counted as a duplicate. Flags on walk legs are ignored, because a walk leg has no ID
  to lend.
- `manual_id` pins an ID. `resync_after()` then continues just past it, still applying
  the skip rule, and only moves forward. A pin with a different prefix doesn't resync.
- Duplicates are detected across **all routes**, not per route. They go into
  `project["duplicate_ids"]`, sorted by `walk_order_key` (`2.9` before `2.11`). Merge
  bumps zone numbers for this reason.

## Timing and distance

Every counted space costs `minutes_per_block / spaces_per_block` (0.2 min by default).
The user asked (2026-11-09) for timing to follow each block's length, at 16 ft of curb
per parking space, because block IDs vary in length and every unsurveyed block used
to cost a flat 2 min.

- A surveyed block takes `spaces × 0.2`.
- An unsurveyed block (`spaces_known: False`) is timed by length:
  `spaces_est = floor(length_ft / ft_per_space)`, then `spaces_est × 0.2`.
- Either way a block takes at least `length_ft / walk_speed_ft_per_min` (the walk
  floor), which matters only for long blocks with few spaces.
- `spaces_est` is an estimate and must never read as a count. It is `None` once
  spaces are entered. The UI shows it with ≈ and "est.". The CSV's SPACES stays blank
  for unsurveyed blocks, and SPACES_SOURCE stays "not surveyed". `totals.spaces` is
  entered counts only; `totals.spaces_est` sums the estimates.
- Walk legs take distance ÷ `walk_speed_ft_per_min` (default 260, about 3 mph).
- **Lots get a suggested time and add no distance.** The user asked for it
  (2026-11-09), reversing the 2026-11-08 rule that lots stay untimed.
  - `minutes_suggested` = lot spaces × 0.2. Those are the surveyed spaces, or
    `spaces_est = floor(area_sqft / lot_sqft_per_space)` (default 325).
  - `minutes_manual`, when set, replaces it in `minutes`.
  - Lot minutes go into `totals.lot_min` and `total_min`. `count_min` stays block
    faces only.
  - Every place that shows totals says lot times are suggestions: `#lotnote`, the
    lot's row, and the viewer's header and sidebar. The PDF and SVG show no times.
- `totals.blocks` counts block faces only. `totals.lots` and `totals.lot_spaces` count
  lots. `totals.spaces` is entered counts, block faces and lots together.
  `totals.unsurveyed` counts unsurveyed blocks and lots. `grand_totals` has the same
  keys, including `lot_min` and `spaces_est`.
- The CSV's columns must not change, because they feed Survey123. A lot's
  `EST_MINUTES` is now filled with its allowance.
- Distances are great-circle (`haversine_ft`, `EARTH_RADIUS_FT = 20902231.0`) along
  the clicked vertices. They measure the drawn path, not the true curb line.

## HTTP surface

- `GET` `/` (and `/index.html`), `/api/state`, `/api/export/meta`, `/api/geocode?q=`,
  `/api/projects`, `/api/load?name=`,
  `/api/export/{csv,gis,geojson,svg,pdf,viewer,json}`
- `POST` `/api/state`, `/api/save`, `/api/new`

Saving (`save_project()`):

- `STATE["file"]` is the saved project the open one belongs to. `/api/load` and a
  successful save set it; `/api/new` clears it. `/api/projects` returns it as
  `current`.
- `/api/save` takes `{project, force}`:
  - `force: false` (Save, autosave and the closing-tab beacon all send it) refuses to
    replace an existing file that isn't `STATE["file"]`. It replies
    `{conflict: true, file, path}` and writes nothing.
  - `force: true` writes anyway. The Save button asks with `confirm()` first.
  - No `force` key at all keeps the old always-write behaviour for old pages and
    scripts.
- Writes go to `<name>.json.tmp` and are then `os.replace`d, under `SAVE_LOCK`.
- Import calls `/api/new` before `/api/state`, so an imported file starts tied to
  nothing and can't be autosaved over a saved project of the same name.

Geocoding proxies to OpenStreetMap Nominatim with an identifying User-Agent, as
their usage policy requires. The UI searches only on Enter: the policy forbids
search-as-you-type against the public server.

## Exports

- **CSV** seeds Survey123. Its columns must not change.
- **GIS zip for ArcGIS** (`export_gis_zip`): block faces, lots, route lines and
  start/end points as separate GeoJSON files, plus the CSV, a `schema.ini` and a
  README. It feeds the user's ArcGIS occupancy workflow, which uses JSON To Features
  and then a one-to-many join on a **Text** `INV_ID`. Checked against ArcGIS Pro's
  docs:
  - A feature class holds one geometry type, hence one file per type.
  - The first feature in a file sets the field types, so `_feature_collection` puts
    the most complete feature first. Every feature in a file carries the same fields.
  - `ORDER` is a reserved word, hence `WALK_ORDER`.
  - Without a `schema.ini`, ArcGIS guesses the CSV's `INV_ID` is a number and the
    join fails ("No join was possible").

  Field names are uppercase and match the CSV. Polygon rings are counter-clockwise
  (RFC 7946), and invalid geometry is skipped.
- **GeoJSON, one file** (`export_geojson`): the same features, mixed geometry, for
  QGIS.
- **SVG** has one named `<g>` layer per route, for Illustrator/Figma.
- **PDF** is written byte by byte, with no reportlab.
- **Standalone HTML viewer** fills `VIEWER` with computed data.
- **Project JSON**. This is the one to keep working from (the Export menu lists it
  first under "To keep working later"); it reopens with Import file…. The UI builds
  it in the browser from `strip(P)`, so it works even if the server has stopped.
  `/api/export/json` still returns the same thing for scripts.
- **PNG** is browser-side only: the UI draws the SVG onto a canvas at 2× size.

The other server exports download through a temporary `<a download>` rather than
`location.href`. A navigation would fire `beforeunload` and show "Leave site?" on
every export while a save is pending.

The SVG the UI downloads isn't the server's SVG as-is. `svgWithBasemap()` fetches map
tiles using `/api/export/meta` (`svg_geometry()`) and inlines them at the
`<!--BASEMAP-->` placeholder. `svg_geometry()`, `export_svg()` and `export_pdf()` all
get their bounds and scale from `_plan_frame()`, so they can't drift apart.

Free text (names, notes, manual IDs) is escaped everywhere it becomes markup:
`esc()` in the UI and in `VIEWER`, and `html.escape` in `export_svg()`.

## Browser-side state

- `push()` sends one `POST /api/state` at a time and drops replies that are already
  stale. Don't call `api('/api/state', …)` directly for an edit; go through `push()`,
  so the threaded server never ends up with an older project than the screen.
- `freshHistory()` resets undo/redo after opening, importing or starting a project.
  Merging is an edit and goes through `push()`, so it can be undone.
- **Autosave and leaving** (section `// ---- saving, autosave and leaving the page`):
  - `push()` calls `edited()`, which bumps `editVer` and, with autosave on, starts a
    1.5 s timer. Unsaved means `editVer !== savedVer`.
  - `saveNow()` chains saves one at a time. Each save waits for `push()` to land
    first.
  - `markClean()` runs after New, Open, Import and the first load.
  - `#savestate` in the footer shows the state persistently; `note()` is still the
    transient message.
  - `beforeunload` asks when there are unsaved edits, Shift-click bends or lot
    corners in progress. `pagehide` sends a last `force: false` save with
    `sendBeacon`.
  - New, Open and Import call `okToReplace()`, which saves first or asks.
  - The autosave on/off choice is in localStorage (`route-mapper-autosave`).
- **Curved blocks** (`bendPts`, `finishBends`, `undoBend`, `updateBendBar`):
  - In Count or Walk, a click with Shift (or Alt/Option) adds a bend to the leg being
    drawn instead of ending it. The next plain click lays one leg through all the
    bends.
  - Enter ends at the last bend. Backspace or ⌘Z takes one back. Switching tools or
    route tabs ends at the last bend.
  - Leaflet's box zoom is disabled while Count or Walk is the tool, because it's
    Shift-drag and a wobbly Shift-click would zoom.
  - A plain click within 6 px of the last point no longer lays a tiny block.
  - The user asked for curves (Nov 2026): clicking around a curve gave every bend
    its own ID, and clicking only the ends cut the corner.
- **Merge with next** (`mergeWithNext`, `M`): joins the next non-lot leg onto the
  selected one, keeping every corner. They must meet end to start and be the same
  kind. It keeps the first block's uid, ID and details, sums spaces, and re-ties lots
  from the absorbed leg. This is how a curve already split into several IDs is fixed.
  `dissolveVertex` (Delete on a joint) also merges but drops the shared corner.
- **Separating and rejoining ends** (`drawEndTabs` / `rejoinEnd`): the selected leg
  gets two end tabs over the shared corners (corner handles move every leg at a
  point; tabs move one leg's end). On drop, `snapTarget` (ignoring the leg itself)
  places the end.
  - If it now meets another leg the right way round (start onto end, or end onto
    start) and they are already adjacent in walk order, apart from walk legs, those
    walk legs are removed and nothing renumbers.
  - If they meet but aren't adjacent, the leg is moved beside its new mate.
  - Otherwise it just stays where it was dropped, keeping its place and number.

  The user asked for this (Nov 2026) to rewire a block onto the end of a newly added
  missed block.
- **Inserting a block** (`insertMode`, `setInsertMode` / `drawMidHandles` /
  `insertPoint` / `splitLegAt`, in the section marked `// ---- inserting a block`):
  - Works like ArcGIS Online line editing. In insert mode, every stretch of every leg
    on the active route gets a white midpoint handle. Dragging or clicking one splits
    the leg there: the first half keeps the uid, ID and details, the second half is a
    new leg on the same street, and tied lots re-tie. `breakAway` (Alt/Option held)
    bends instead: the point is added to the same leg, with no new ID.
  - A handle under an ID badge is nudged about 26 px along its stretch so the badge
    doesn't block it. Insert mode re-renders on zoom to keep that offset right.
  - This replaced "Add missed blocks" (`ins` / `finishInsert` path stitching, Nov
    2026). The user found it unreliable and asked for ArcGIS-style midpoint editing
    instead. Don't bring it back.
  - `I` toggles insert mode, Esc or any drawing tool ends it, and `F` / **Flip
    direction** reverses one leg's points (`flipLeg`).
- **Map rotation:** leaflet-rotate, pinned to 0.2.8. 0.3–0.5 came out in a rush in
  Oct–Nov 2026, so stay on 0.2.8 until they settle. Right-click and drag is our own
  handler on the map container. The plugin's compass control resets the map to north
  up; it paints its button orange, which CSS overrides. With rotation on, any custom
  pane must be created in `map.getPane('overlayPane').parentElement` (the rotating
  pane), or it draws in the wrong place. Arrows redraw on `rotate`. Exports are always
  north up.
- **Reference layers** (section `// ---- reference layers`):
  - Purely client-side overlays on a canvas in `refPane` (z 350, under the routes).
  - Never part of `P` or the project, because every edit posts the whole project.
    They persist in IndexedDB (`route-mapper` / `kv` / `refs`).
  - Parsers: CSV (lat/lng columns, WKT or "(lat, lng)"), GeoJSON, ArcGIS JSON,
    KML/KMZ (DOMParser), and zipped shapefiles (hand-rolled zip reader using
    `DecompressionStream('deflate-raw')`, .shp/.dbf/.prj).
  - Web Mercator is converted; other projections are refused with a message.
  - Clicks only open a popup in Select mode; otherwise they bubble to the map so
    drawing works over them.
  - Checked in Node against the real City of Oakland meters CSV (4,872 points) and
    generated GeoJSON/ArcGIS JSON/shapefiles.
- Colours: the UI is dark slate with a sky-blue `--accent` (#5AA9F2). The user asked
  for no black-and-orange look (Nov 2026), so don't bring back amber/orange accents.
- The main UI has no narrow-screen layout. Below about 1000 px wide the map column
  collapses to nothing. When testing in a small preview pane, emulate a wider viewport.

## Constraints

1. `STATE` is a single module-level dict holding one project. The server is a
   `ThreadingTCPServer`, but there is no per-session state and no locking. This is a
   single-user local tool.
2. The UI exists in two copies: `HTML` here and `index.html` in the Pages build. Change
   both, or the two builds drift apart.
3. Likewise, `compute()` and the exports exist here and again in `engine.js`. The
   arithmetic must stay identical.
4. Standard library only is a hard constraint, not a preference. It is why the PDF
   writer is hand-rolled. It applies to the Python. The page loads Leaflet 1.9.4 and
   leaflet-rotate 0.2.8 from unpkg, both pinned, and nothing else.
5. Several people each run their own copy on their own computer. Nothing is shared
   through a server; projects move between people as JSON files (Import / Merge).
